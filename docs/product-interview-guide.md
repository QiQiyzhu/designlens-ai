# Product interview guide — 30 questions

Use these as preparation, not a script to overstate completed work. Real user research remains **PENDING REAL USER RESEARCH**. AI-assisted coding and documents must be disclosed when discussing personal ownership.

1. **为什么做这个产品？** 想验证产品决策的证据在工具间交接时是否丢失；价值不是多生成一份PRD，而是让别人复查“为什么做、为什么用AI、凭什么继续”。目前这是假设。
2. **用户是谁？** 初始是独立PM或小团队产品负责人，复核者可能是设计师或工程师。企业研究运营需要权限和集成，超出当前MVP。
3. **用户最痛的问题是什么？** 尚不能声称已知。准备通过近期真实决策回放和新玩家任务观察，找出严重、重复而非仅被口头抱怨的问题。
4. **证据是什么？** 竞品官方资料说明市场能力；源码和执行报告说明系统行为。没有真实玩家访谈或产品效果证据，两者不能互相替代。
5. **具体访谈了多少人？** 当前提供的数据是0人。8–12人是计划招募规模，不能说已经访谈。回答这一点比编造结论更重要。
6. **如何设计访谈？** 先观察最近一次真实行为，再问当时意图；记录原话、操作和解释，避免推销AI方案。允许反例、不喜欢AI的用户和放弃任务的人进入分析。
7. **为什么选择这个需求？** 当前先选择可验证的决策链工具MVP。真正的游戏功能要等真实反馈聚类、top3问题和非AI比较后再选。
8. **如何做优先级？** 先看问题严重性和证据，再使用RICE/ICE/MoSCoW帮助讨论。Reach等是有单位的估计，不拿访谈条数伪装覆盖规模；最后由人写理由确认。
9. **为什么一定要AI？** 不一定。信息层级、文案和有限规则问题可能根本不需要AI。Canvas必须允许No AI成为正常结论。
10. **为什么不用传统规则？** 我会先用规则做基线。仅当任务语言变化大、规则维护不合理且模型方案在质量/成本/延迟上胜出时才考虑AI。
11. **RAG和Agent什么时候用？** RAG用于依赖外部更新证据的回答；Agent用于确实需要多步工具选择的任务。只读取游戏状态并给解释通常不需要自主Agent。
12. **如何控制幻觉？** 不把citation当真相。MVP使用原文摘录、校验ID/quote、没有证据就abstain、保留人审。更自由的解释需要语义审查、负例和未见数据评测。
13. **如何评估AI产品？** 分开任务完成、格式、证据、错误、成本、延迟和人类体验。当前开发fixture能测契约，不能证明真实用户价值；LLM judge也不能单独裁决。
14. **什么叫好的AI产品指标？** 指向用户完成的决策或任务，有明确分母、时间窗和护栏。生成次数很容易增加，但可能只是制造更多审查工作。
15. **Prompt修改怎么验证？** 版本不可变，保存diff、模型/配置、数据集hash和逐case输出。重新跑固定case，再做盲审。默认extractor不理解prompt文字，因此其结果不能冒充模型调优。
16. **如何设计North Star？** Weekly Validated Product Decisions。必须有真实证据、实际评测/研究结果和人类build/revise/stop决定；创建实验草稿不算。
17. **如何埋点？** 记录项目、source、insight审核、opportunity、workflow、evaluation、experiment生命周期，带UTC时间、实体ID和demo标记。避免把重复点击当独立接受。
18. **SQL分析了什么？** DAU/WAU、按项目排序漏斗、成熟激活队列、功能采用、人审接受率和workflow成功率。暂无真实用户队列；演示事件只验证查询正确。
19. **模型成本上涨怎么办？** 先测每个有效决策的成本；缩小上下文、缓存不敏感结果、降低调用频率、比较小模型/规则。不能只看单token单价而忽略重试和人审成本。
20. **延迟从2秒变8秒怎么办？** 查是检索、推理还是重试；看任务是否容忍等待。允许先显示来源和可取消的处理中状态，必要时规则即时回答并标注差异；不伪造流式成功。
21. **算法团队说做不了怎么办？** 先澄清失败是数据、准确率、成本还是边界；收缩问题并评估非AI方案。这个项目没有真实算法团队，角色协作材料只是planning exercise。
22. **研发资源减半怎么办？** 保留导入、证据复查、人类决定和一个可测任务，砍任意工具连接、多租户和复杂画布。完整的小闭环胜于大量不可执行按钮。
23. **MVP砍掉什么？** 自动游戏建议、任意MCP/Agent执行、音视频转录、实时协作、企业权限/计费和大规模实验分流。
24. **用户说好用但留存没提升？** 区分礼貌反馈、任务效用与使用频率。检查是否解决一次性任务、回访场景是否存在；不为了追留存强加通知或降低用户控制。
25. **AI指标提升但体验下降？** 技术指标可能与任务脱节，或延迟/阅读负担增大。看用户完成任务和护栏，重新定义rubric，而不是用更高benchmark分数否定用户行为。
26. **最大失败是什么？** 当前最大风险是把一个实现完整的工具误认为已验证产品。没有实地研究就无法证明需求；这是明确的证据缺口，不编造一次不存在的商业失败。
27. **重来会改什么？** 更早让一个不熟悉项目的人用现有工具和原型各复查一次决策，先测结构是否有价值，再增加字段。
28. **与直接ChatGPT有什么区别？** 不是模型更聪明，而是ID关系、人审状态、版本和评测/实验契约默认存在。但ChatGPT+文档模板可能够用，要通过实际对照验证迁移价值。
29. **与Dovetail/ChatPRD/Amplitude区别？** Dovetail已有证据链和研究能力；ChatPRD强于产品文档；Amplitude强于行为分析与实验。DesignLens试验的是跨可行性、workflow和评测的窄交接，不声称功能全面超过它们。
30. **如何规模化？** 先证明小闭环价值，再优先现有工具导出/集成。多人托管需要身份权限、数据隔离、审计和预算；付费意愿、用量和维护成本都要用真实数据验证。

## Three-minute demonstration
30s：说明假设、竞品与真实研究缺口。45s：打开证据并人审一个合成观察。45s：创建机会并显示No AI/规则对照。45s：修改版本、运行、审批、打开失败case。15s：说明下一步真实研究和哪些结论不能写简历。不要先从技术栈或代码行数讲起。
