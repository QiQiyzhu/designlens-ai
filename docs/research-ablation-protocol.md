# Reviewed Research V2：冻结的开发评测协议

此协议在付费执行前提交。数据为 [12 条人工编写的合成开发案例](../evals/research-intake-dev-v2.json)，覆盖相关/无关材料、敌意文本与合法观察、邮箱/电话、手工姓名/地址、中文、反例、数字误清理、空证据。不是独立保留测试集；没有真人访谈或模型合成的“真实用户反馈”。

## 固定处理条件

三种变体使用同一 DeepSeek 传输、模型配置、结构化系统指令、输出上限和自动评分；每个案例轮换变体顺序，并在回执保留顺序、模型响应、用量和每次请求摘要。

| 变体 | 处理 | 所回答的问题 |
|---|---|---|
| direct-synthetic | 直接发送此文件中的虚构标识符与来源 | 没有本地清理时，哪些标识符会外发或出现在回答中？ |
| local-cleanup | 本地规则及已预先声明的手工替换词清理来源与问题 | 单独加入清理，保留任务信息与暴露标识符的权衡如何变化？ |
| cleanup-and-context-gate | 同样清理，再词汇检索；零上下文在模型前停止 | 额外上下文门槛减少多少调用，又遗漏哪些有效来源？ |

直接合成变体故意绕过应用的隐私门，仅通过固定仓库夹具调用传输层，用于观测基线风险；脚本不接受外部数据集路径，拒绝非合成来源。真实应用没有“绕过清理发私人材料”的开关。

## 指标与失败

每条记录检查 JSON 格式、引用与实际送入上下文一致、必需内容、来源覆盖、预声明弃答行为和虚构标识符输出；全部通过才算该开发契约通过。分别记录**实际送达模型的标识符案例数**与**输出标识符案例数**，不以“模型没说出来”掩盖输入已外发。

`numeric-non-pii` 故意保留合法版本号 `12345678`，可以暴露电话规则过度清理；不为刷通过率移除这个困难案例。敌意文本没有合法观察时应弃答，带有合法观察时需要保留与问题相关的证据。人工可用性、语义相关性和真正的攻击安全性仍待另行审阅，不由字符串检查证明。

主要展示每个变体的逐案例结果、处理前/后风险与失败类型。36 行小样本不报告泛化准确率、统计显著性或生产 P95；重复执行也不会变成新增独立案例。

## 运行与预算

按 [DeepSeek 配置](real-model-setup.md) 设置服务端环境变量后：

```powershell
.\.venv\Scripts\python.exe -m scripts.research_ablation --output outputs/intake-preflight.json
.\.venv\Scripts\python.exe -m scripts.research_ablation --execute --max-calls 36 --max-observed-tokens 25000 --max-seconds 300 --output outputs/intake-ablation.json
```

默认预检零调用。一次完整比较计划 36 行，最多 36 次请求；上下文门拦截的案例不会调用模型。`--repeats 1..3` 可声明重复次数，同时相应设定 `--max-calls`（上限 120）。没有自动重试；429、协议失败或传输失败停止并保留部分回执。预算停止状态为 `budget_stopped`，不得作为完整实验。

用量和时间预算在请求之间检查，无法追回已发出的请求；一次在途请求可能使已观测 token 超过阈值，失败用量也可能未知。默认单次最大输出 768 token（环境变量限定 64–2000），错误和未知账单保留 null。回执每行写入后原子替换，额度或进程中断不会把未执行行填成成功。

记录执行 commit、代码和数据集 SHA256、提示配置摘要、模型/响应模型、HTTP 状态、用量、逐例输出、时间及失败。更改数据、提示或规则必须生成新版本；先观察结果再改旧评分不属于本协议。
