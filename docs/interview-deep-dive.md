# DesignLens：从“引用是对的”讲到“现在不能做决定”

[完整案例](decision-case-study.md) · [真实执行数据](../reports/decision-case.json) · [研究准备](research/arc-shift-plan.md)

## 30 秒版本

“我给这个产品保留了一条不漂亮的结果：问题问武器共鸣，结构化提取却原样引用了发票日期。引文和格式都正确，仍然不相关，所以我没有把有引用当作可以做产品决策。加检索和 context 条件后，这个合成案例会在模型前停止；有内容的候选则停在人审。12/12 只是开发规则通过，10 条还待审批，真实用户数和有效产品决策数都是零。下一步是带停止规则的真实研究，而不是先把 AI 功能做出来再找证据。”

## 3 分钟版本

**第一分钟，展示反例。** 打开 `irrelevant` 的四个 variants，先让面试官看到“发票周二到达”的原始来源，再看 V2 的 valid grounding=true 与 abstention=false。说明我修正的是判断层次：格式、可追溯性和相关性不能用一个分数替代。V1/V2 由确定性 extractor 的 output_mode 驱动，不是一次 LLM 提示词能力提升。

**第二分钟，展示停止。** Workflow 只有 Input、Retrieval、Condition 三步，零上下文直接 abstained；有内容的 route 请求则停在人审。服务端对未审观察拒绝创建机会；就算机会确认过，来源后来被否决也不能创建实验。本轮实际 HTTP 422 和 SQLite 状态可看，不只是 Figma 上一个禁用按钮。

**第三分钟，展示研究决定。** 目前没有真实数据，所以不替用户选 AI build advisor。先做 4–6 位 PM 探索访谈和独立的 8–12 位玩家定性计划，人数是目标。记录任务、原话、独立参与者和反例；不足时补采样或保留未决定，非 AI 方案能解决时就停止增加 AI。最后才设计小型可用性试验，结果空着直到真正发生。

## 被拒方案和明确代价

1. **只让模型加引用**：本案例显示引用有效也可能答非所问；需要相关性和人判断。当前关键词过滤只是窄范围改进，不是通用语义判定。
2. **用合成 12/12 当产品成功**：12 是开发 fixture 数，10 条未审，真实参与者 0；技术契约和业务验证要各自计数。
3. **把访谈计划写成案例成果**：会把招募目标偷换成样本。`metadata-not-outcome` 明确保留 planned；North Star 不因此增加。
4. **先做自主 Agent 找功能**：没有自主工具调用的真实需求证据，增加不可控变量。当前拒绝任意 MCP/Agent 执行，仍可比较 No AI、Rules、Search、RAG 等方案。
5. **一次接受的观察永远有效**：后来否决应重开机会；否则流程形式上有人审、实质上仍可用过期证据推进。

这种选择牺牲了“一键自动出结论”的顺滑感，需要人做真实判断。SQLite 和单人本地工作区适合展示决策链，尚不能承担无保护的真实研究托管。

## 五个追问

1. **Prompt V2 提升 11 个 case，算提示词优化吗？** 只能叫输出契约从 plain 改 structured 的实际确定性对比。extractor 不理解 prompt prose；没有推理模型调用，不能声称 LLM 质量提升。
2. **为什么 RAG 能过滤这条发票材料？会漏相关证据吗？** 当前本地词汇检索与问题没有有效交集，所以上下文为空；它可能漏同义表达，也可能收偶然重叠。必须新建真实问题验证，不把一条成功等同语义理解。
3. **人确认了为什么还拦实验？** 支持该确认的 insight 后来变成 rejected。代码重新读取来源状态，返回 422；原确认不是绕过新反证的永久授权。
4. **要访谈多少人才够？** 4–6 位 PM、8–12 位玩家是准备目标，不是统计证明。按任务与熟悉度覆盖采样，观察重复问题和反例；遇到薄弱分层补采样，达到预定上限仍不清楚就保留结论不足。不能用重复评论冒充独立人数。
5. **什么时候应该不用 AI？** 若固定标签/规则能提供必要信息、任务重复性高且维护成本低，先试它；若探索访谈连问题都未证实，暂不选任何干预。No AI 是会被实际比较的方案，不是文档装饰。

## 下一实验与停止点

先执行[已准备的研究协议](decision-case-study.md#4-从待访谈转为采样与停止规则)，得到同意、任务观察和真实材料。反复问题未出现就停止产品扩展；出现后再比较当前方法与证据包，对照非 AI 方案。拒绝把任务时间差预填为“提升 X%”，也不把小型定性试验包装成统计 A/B。

## 面试追问：接通 DeepSeek 后，结论为什么没有自动升级

新增 [DeepSeek 服务端适配与最多三次探针](real-model-setup.md)，模型响应、引用合法性、任务相关性、人工判断、真实用户价值是五层不同证据。远程模型可以产生候选；HTTP 200 不代表 schema 合格，schema 合格不代表相关，相关也不代表需求已经验证。模型调用发生在合成来源上时，真实参与者仍为 0。传输层用 19 项额外检查覆盖错误地址、429、截断、拒答、超时、调用上限和零调用预检；这些不是模型质量评测。

可以这样讲设计取舍：先保留可重复的 extractor 基线，再把真实模型接到同一引用和人审边界中；成本与失败可见之后，才有依据决定模型的额外不确定性是否值得。相同的历史结果不会因为换了 Provider 就被改写成一次新的模型成绩。

首次 [真实 DeepSeek 回执](real-model-results.md) 已产生：3 次响应、2 例契约通过。第三例把敌意材料直接弃答，违反原有引用覆盖契约；这不是泄密失败，也不能改成安全能力成功率。把它拿给面试官看，说明你会先区分“安全边界”与“完成研究任务”的评价目标，再设计新的样本和标准，而不会看到结果后修改旧分母。合计 874 token、人工评价仍 pending、真实研究人数仍为 0。
