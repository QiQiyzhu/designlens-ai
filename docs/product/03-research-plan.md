# Research plan

**PENDING REAL USER RESEARCH**. No sessions have been represented as completed.

## Questions
1. Where does evidence get lost in a recent real product decision?
2. Which claims need a reviewer, and what makes that reviewer trust them?
3. Does linking an opportunity to evaluation and an experiment improve the decision, or add administration?
4. For ARC//SHIFT, what do first-time players misunderstand before making a build or route choice?

## Method
First conduct 4–6 exploratory PM interviews (a proposed target, not a sample achieved), using a recent redacted decision artifact. Then run the [ARC//SHIFT 8–12 person qualitative pilot](../research/arc-shift-plan.md). Interviews establish problem language before prototype testing. Observe tasks before asking for explanations; avoid introducing an AI advisor as the intended solution.

## Data and analysis
Save raw consented notes with source_id, pseudonymous participant, session date, segment and type. Each observation carries a verbatim excerpt and source ID; interpretations are separate. Two passes: open coding without the product's feature labels, then candidate themes with counterexamples. Count unique participants, not duplicate comments. Frequency in a convenience sample is not population prevalence.

Have a second reviewer, if available, review disputed coding. If only one researcher exists, record that limitation rather than inventing inter-rater agreement. Maintain a negative-case list and an assumption ledger. Export a read-only analysis snapshot before selecting the top three problems.

## Decision gates
Do not select a real AI feature until a repeated task problem is observed and a non-AI alternative is considered. If evidence is sparse, do another qualitative round; no significance claim. Consent, recruitment, raw evidence and actual sample counts must be complete before converting any case study field from pending to observed.

## Deliverables and timing
Prepare consent/script now. Recruitment and session dates remain owner-scheduled. After each session: redact and index. After the pilot: cluster, identify top three evidence-backed problems, compare alternatives, select one MVP and preregister a usability test. Templates are supplied in docs/research and contain no fake answers.
